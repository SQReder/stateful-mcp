# Stateful Coding Worker

Локальный MCP-сервер для корпоративного Kilo Code. Реализованы I0–I2:
stdio transport, text-only inference, долговечные сессии с выбранными снимками
исходников, кандидаты и review loop. Сервер читает явно выбранный контекст и
пишет только своё хранилище; применение кода, компиляция и Git ещё не реализованы.

Нужны Node.js 24+ и npm. Подготовка и проверки:

```powershell
npm ci
npm run typecheck
npm test
```

Тесты используют локальный fake HTTP backend; реальных модельных запросов в
`npm test` нет. `npm test` также собирает TypeScript и проверяет stdio MCP.

Конфигурация — доверенные переменные окружения, не аргументы tool:

| Переменная | Назначение |
| --- | --- |
| `WORKER_BASE_URL` | Полный базовый URL API, включая `/v1` |
| `WORKER_MODEL` | Реальный идентификатор модели на этом endpoint |
| `HARNESS_MODEL_API_KEY` | Существующий ключ, передаваемый как Bearer |
| `WORKER_TIMEOUT_MS` | Таймаут подключения и чтения ответа; по умолчанию 60000 |
| `WORKER_WORKSPACE_ROOT` | Обязательный абсолютный корень проекта для session tools |

`worker_diagnostics({})` проверяет конфигурацию без inference.
`worker_instruct({ message })` делает ровно один запрос без tools и retries,
возвращает полный текст либо безопасную диагностику. Неполный ответ и попытка
tool call считаются ошибкой. Этот вызов не хранит диалог.

`session_start` создаёт сессию с одним `*.test.ts(x)` allowed path.
`context_set` заменяет brief, acceptance criteria и снимки выбранных файлов,
увеличивая revision. `worker_chat` делает один inference: текущий контекст,
текущий запрос и, пока нет кандидатов, только последний успешный обмен;
вся история сохраняется.
`session_status` по умолчанию возвращает компактные счётчики и состояние.
`includeDetails: true` явно открывает полные brief, snapshots, turns и errors.

На I2 `worker_chat` просит у модели один JSON-объект
`{"path": "<allowed path>", "content": "<полный тестовый файл>"}` без Markdown.
Если ответ корректен и path точно совпадает с allowed path, создаётся
неизменяемый кандидат: `candidateId`, полный код, снимок целевого файла на
момент генерации, unified diff полной замены этого файла и revision. Иначе
кандидат не создаётся: ответ модели сохраняется в turns, а tool возвращает
`candidateDiagnostics`. Код не обрезается и не исправляется сервером.

`candidate_read` возвращает полный код и diff кандидата, его revision, текущую
revision и историю ревью; устаревший кандидат помечается `stale`.
`candidate_review` одобряет или отклоняет конкретный кандидат на текущей
revision и добавляет findings в историю. Устаревший или уже отклонённый
кандидат одобрить нельзя — нужна новая версия. Следующий `worker_chat`
получает текущий контекст, последний кандидат один раз и его findings, если
он отклонён; замечания к более старым версиям в prompt не попадают. Ни один
из этих tools не пишет в рабочие файлы проекта.

SQLite фиксирована в `<workspace>/.stateful-worker/state.sqlite`, содержит полные
исходники и тексты диалога; каталог исключён из Git. Одна DB обслуживается одним
MCP-процессом: второе соединение блокируется.
Во время inference эта сессия занята; после crash незавершённый ход помечается
`interrupted`, запрос автоматически не повторяется.

Бюджет I1 — консервативная эвристика UTF-8 bytes + 256, а не точный tokenizer:
warning 24000, hard input 32000, output reserve `max_tokens: 8192`.
Проверки выполняются до чтения больших файлов и до inference; обрезания нет.
Ошибка оценки относительно tokenizer неизвестна. Реальный `usage` берётся
только из backend; отсутствующие input/output counts возвращаются как `null`.

Снимок читается через дескриптор, открытый только на чтение, с ограниченным
буфером и сравнением идентификатора файла без потери точности. Путь и время
изменения проверяются до/после чтения; при обнаруженной подмене контекст не
сохраняется. Это не атомарная проверка конечного пути средствами Windows;
механизм не рассчитан на намеренную подмену путей сторонними процессами.

Для разрешённой живой проверки, когда ключ уже есть в окружении:

```powershell
$env:WORKER_BASE_URL = 'https://localhost:8317/v1'
$env:WORKER_MODEL = 'gpt-6-luna'
npm run smoke:live
```

Эта команда вызывает модель через MCP stdio и выводит только безопасные
метаданные. Проверка на временной модели `gpt-6-luna` прошла.
Целевой Qwen3-Next ещё не проверен. Сервер не подставляет другую модель автоматически.

TLS проверяется с системным хранилищем CA. Подключение к корпоративному Kilo
описано в [инструкции](docs/setup/kilo.md). По результатам пользователя от
2026-10-13 корпоративный Kilo вызвал оба tools; `qwen2-5-coder-32b-instruct-awq`
ответила `READY`. По решению пользователя механика развивается локально с
`gpt-6-luna`; доступ и качество целевой Qwen3-Next проверяются отдельно при
deployment/пилоте и не блокируют I1.
